# Idiomas del panel

El panel (`apps/dashboard`) está en **español** (idioma fuente) e **inglés**. Se cambia con el botón
de idioma de la barra superior; la elección se guarda en el navegador (`tiklive.locale`) y la página
se recarga. Los overlays (`/screen`, `/overlay`) no tienen texto propio que traducir.

## Cómo funciona

- Los textos usan `@angular/localize`: `i18n` / `i18n-<atributo>` en las plantillas y
  `` $localize`texto` `` en el código. El español es el texto original, así que no hay un archivo
  `es`.
- `src/main.ts` carga `src/locale/messages.en.json` antes de arrancar la aplicación cuando el idioma
  es inglés. Es una sola compilación para todos los idiomas.
- `src/app/core/locale.ts` guarda el idioma y da el formato de números y horas (`numberLocale`).

## Añadir o cambiar un texto

1. Escribe el texto en español con `i18n` (plantilla) o `$localize` (código). En una plantilla, un
   texto dentro de `@if`/`@switch` va en `<ng-container i18n>…</ng-container>`; no uses cadenas
   dentro de `{{ }}` ni de `[atributo]="…"`: calcula el texto en el componente con `$localize`.
   Si un `$localize` empieza con `:` justo después de un `${…}`, escápalo (`\:`).
2. `npm run i18n:extract` actualiza `src/locale/messages.json` (catálogo de mensajes fuente).
3. Añade a `src/locale/messages.en.json` la traducción de cada identificador nuevo, con los mismos
   marcadores `{$…}` que el original.
4. `npm test` falla si falta una traducción, sobra una o cambian los marcadores. CI vuelve a
   extraer y falla si `messages.json` no está al día.

## Fuera de alcance

- Los mensajes que escribe el servidor (errores de la API, `lastError` del conector, mensajes de
  validación de `contracts`) siguen en español. Las alertas de salud sí se traducen por su código.
- Las plantillas de texto que se guardan como datos (alertas, celebración de metas) quedan como las
  escribió el usuario.
